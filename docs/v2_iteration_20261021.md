## 实现变化

1. **更可靠地识别接口与完整答案。** 支持题面中的模块签名、参数和 `automatic/static`；识别整数类型与多维 packed 位宽。无法确定的类型或参数宽度保持 unknown，避免把合法接口误判成 1 位。截断目标模块或辅助模块不能覆盖已有解。
2. **给验证与修复留预算。** 服务传给子进程的预算不超过实际等待时间，修复此前外层提前终止子进程的问题。模型调用按用途分配上限，默认单题总预算仍为 900 秒。
3. **先归因，再修复。** 自建测试台首次失败时，由同一主模型根据题面推导失败激励。确定归因必须含题面依据、刺激、规格期望、DUT 实际值、测试台期望；标签与三个值不一致时按 uncertain 停止，不修改 DUT 或期望来强行通过。
4. **保留验证更充分的候选。** 不同代码只有通过更高一级检查才覆盖当前解；相同等级保留先前候选。同一份代码的新验证事实会写入记录。较弱或截断的修复稿不能覆盖已通过仿真的结果。
5. **修复输入保留关键证据。** 诊断结论与失败激励进入下一轮，长测试台不再挤掉日志。测试台只从题面独立生成；除编译/系统任务语法修复外保持固定。
6. **增加 6 道独立开发题。** 覆盖饱和运算、复位/使能优先级、ready/valid 停顿、非二次幂深度 FIFO、使能间隙与模式重叠、轮询仲裁。生成输入和评测参考文件分目录隔离。

| 调用 | 剩余时间占比上限 | 秒数上限 | 输出 token 上限 |
| --- | ---: | ---: | ---: |
| 首次设计 | 50% | 360 | 8192 |
| DUT 修复 | 65% | 360 | 8192 |
| 独立测试台 | 45% | 120 | 3072 |
| 测试台语法修复 | 35% | 90 | 3072 |
| 失败归因 | 20% | 45 | 768 |

各调用提前结束后，未用完时间留给后续步骤；这些是方案内部策略，不改变官方 baseline 的 16384 token / 840 秒常量。`LLM_MAX_TOKENS` 仍可进一步降低方案上限。

## 已完成的验证

- Windows 完整 Python 回归 **94/94 通过**，含真实本机 HTTP、子进程及 Icarus 工具链检查；日志为 `D:/fgpa/output/v2/unit-tests-final.log`。其中模型替身用例只验证程序行为。
- Icarus 13.0 题集校验：6 份正确参考全部通过，6 份故意错误的实现全部编译成功且被功能检查检出。另验证提前 `$finish` 不能伪装成完整通过。证据为 `D:/fgpa/output/v2/fixtures/`。
- 第一轮真实 DeepSeek 开发对照：V1 与初版 V2 在 6 题上各生成一次，单题 240 秒、temperature 0.2、思考关闭，独立 Icarus 均为 **5/6**。生成器只看 prompt.txt。它证明初版 V2 尚未在这批样本上提高通过率，原始失败记录完整保留在 `D:/fgpa/output/v2/deepseek-comparison/`。

第一轮暴露出：归因模型可能给出与解释不一致的标签；同等级修复稿可能覆盖较早候选；历史窗口的位序容易与注释不一致。最终版增加了三个值的归因一致性校验、保守候选选择，以及按实际移位表达式检查位序的通用提示。没有将参考答案或题目专用实现放进提示词或技能包。

第二轮在归因与候选选择修复后仍为 5/6，序列检测依然存在旧计数晚一拍的问题，证据在 `D:/fgpa/output/v2/deepseek-final/`。随后进一步明确通用的 next_history/next_count 逐拍规则，第三轮重新生成全部 6 题，没有复用上一轮通过的答案。

## 发布候选的实际结果

第三轮原始生成和独立评测保存在 `D:/fgpa/output/v2/deepseek-release/`。DeepSeek `deepseek-flash`、思考关闭、temperature 0.2、每题最多 240 秒、每题单次独立生成（内部最多 3 轮）与前两轮相同。Icarus 结果如下：

| 题目 | 独立功能结果 | 失配 / 采样 |
| --- | --- | ---: |
| 有符号饱和加法 | 通过 | 0 / 65536 |
| 计数器优先级 | 通过 | 0 / 1038 |
| ready/valid 缓冲 | 通过 | 0 / 1042 |
| 深度 3 FIFO | 失败 | 394 / 1560 |
| 带使能的重叠序列检测 | 通过 | 0 / 778 |
| 轮询仲裁 | 通过 | 0 / 1120 |

这轮仍为 **5/6（83.3%）**，不能声称整体通过率已超过 V1。序列检测本次修复正确，但 FIFO 出现新失败：其同拍出入分支不论当前占用均向 slot2 写入，未按出队后的实际尾位置写入；该题生成自测时还遇到 API `IncompleteRead`，保留了已编译候选，未完成内部功能验证。后续需要提高这类队列状态转移与网络失败恢复的可靠性。

**本机 Vivado 2025.2 复验完成：5 题 L3，FIFO 为 L1；无工具环境错误。** 使用原样官方分级器、器件 `xczu3eg-sbva484-1-e`、5 ns 时钟，功能失配与 Icarus 一致。报告及原始日志在 `D:/fgpa/output/v2/deepseek-release/independent-vivado/`。这些是自建题和本机旧版本工具的开发判级，不能当作赛事 Vivado 2026.1 或隐藏题成绩。

内部自检只在 3 题通过；1 题判自建测试台错误而停止，1 题因上述网络异常停止，仲裁题用完轮次后保留先前候选。独立功能判定与内部自检结论分别记录，不能互相替代。模型生成的注释也可能与真实位序不一致，不能作为正确性证据。

**本轮完成的是能力相关机制迭代与实测，不是达到正式 70 分。** 没有用不同版本的最好答案拼出 6/6，没有将开发 API 当作正式本地模型，没有计算不具可比基线依据的增益分。这 6 题已用于开发，不称盲测；正式能力提升还需新题集和同配置本地模型多次独立采样验证。

## 运行与继续评测

无需模型即可检查题集：

```text
python scripts/evaluate_suite.py --validate-fixtures --output output/fixtures
```

生成一道题（本机须先配置模型环境变量）：

```text
python -m agent.main --input evals/rtl_generalization_v2/prompts/v2_04_fifo3 --output runs/v2_fifo --backend iverilog --deadline 900
```

用隔离题集评测生成结果：

```text
python scripts/evaluate_suite.py --run v2=results/v2.json --output output/v2-evaluation
```

清单格式和 Vivado 判级命令见 [题集说明](../evals/rtl_generalization_v2/README.md)。只有同配置的本地开源主模型及原样官方 baseline、独立多样本、Vivado 判级，才能形成有关前 70 分的开发估计。当前不计算正式比赛分数，也不计算后 30 分。

本轮未启动新的付费云实例。V1 的 W7900 / Qwen3-14B 云端公开题结果仍是历史证据；V2 尚须在该本地开源模型和 Vivado 2026.1 上复验。商业 API 与小题集的结果不能替代正式离线评测。
