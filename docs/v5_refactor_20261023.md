# V5：清理冗余流程，再优化失败处理

**本轮 V5 千问实测已结束**：同批共同判定 21 题，官方基线 7/21、V4.2 8/21、V5 8/21；同题生成耗时较 V4.2 减少 35.0%。详细结论与范围见 [最新测试报告](v5_qwen_test_20261023.md)。下面较早的待验证描述按迭代当时状态解释。

当前版本：`2026.10.23-v5-qwen-only`。修改前已备份 V4.2；本轮完成源码与 skill 更新及 **173 项本地回归，全部通过、无跳过**。本轮未调用真实生成模型、未启动云实例，云积分消耗为 0。

## 先完成的清理

- 合并测试台初次生成、格式恢复、编译修复的请求解析、日志记录和启用逻辑；错误归属由工具层统一识别。
- 将验证计划的大函数拆成解析、控制/接口校验、算法与刺激转换、固定模板生成，复用声明、复位和数组复制逻辑。旧计划和紧凑计划共用执行骨架。
- 移除每题固定执行的额外设计审查及其提示词、预算项。上一批该步骤调用 19 次、累计 171.06 秒，未证实净通过率收益。
- 移除旧商业 API 连接脚本及健康检查中的旧密钥回退，简化 README 和设计说明；历史结果继续保留在历史报告与备份中。

## 基于千问结果的优化

| 上一批的共性问题 | V5 改动 | 已验证的范围 |
| --- | --- | --- |
| 19 个计划只有 1 个初稿合法，临时量漏声明、字段错配 | `temporaries` 把声明和表达式写在同一记录，`states` 把声明和更新写在同一记录；可靠端口由程序固定，保留 signed | 接口不可改写、未知位宽不猜测、未声明/前向/循环引用提前拒绝 |
| 算术先截断、当前输入漏算、新旧状态和采样混淆 | 明确扩位、同时提交、沿前临时量与沿后组合输出；固定骨架记录真实逐拍输入输出 | 正确符号运算、分组、FIFO 通过；窄位宽 oracle、漏末位 DUT、错采样 oracle 被拒绝 |
| 编译/展开问题被当成功能问题诊断 | 工具记录 compile/elaborate/simulate 等实际阶段与错误源；只有运行断言才进入功能归因 | Icarus 真编译/仿真、Vivado 阶段模拟与错误源分流 |
| 诊断编造实际值或拼接别的采样点 | 必须绑定真实 FAIL 的 sample、全部输入、同名实际值与测试台期望；支持 ModelSim 前缀 | 虚构信号、漏输入、跨样本、不一致或未知态归因被拒绝 |
| 连续三轮相同 DUT，反复沿用旧诊断 | 完全重复候选存稿后停止，不再编译/仿真；一次功能诊断仅支持一次修复，仍失败即停止 | 重复编译失败、接口失败、功能失败及不同坏稿的流程回归 |

程序仍禁止 oracle 读取 DUT 输出。没有把参考答案、固定测试台或题号匹配写入生成流程，也没有放宽 PASS 检查来提高表面通过率。

## 可确认的减耗与仍待测量的性能

无修复的结构化正常路径由 **3 次模型调用变为 2 次**（DUT + 独立计划），删除固定设计审查。验证计划角色提示正文由 **1872 字符缩至 1410 字符，减少约 24.7%**；这是文本长度，未计动态端口契约，也不是实测 token 或吞吐提升。

重复候选不会再运行同一轮 EDA 或触发第三次相同修复。实际模型可能生成不同回复，因此上一批 171.06 秒审查成本只说明优化动机，不能直接当作新版实测节省时间。

**V5 的真实千问通过率、墙钟时间、计划首稿合法率和 oracle 可靠性仍待新一轮同配置测试。** 当前最新模型成绩仍为 V4.2：同批 12 题 baseline 3/12、V3 3/12、V4.2 2/12。新版本没有正式成绩或达到前 70 分的证明。

观察绑定只能核实实际值，不能证明模型从题面推导的期望正确；语义字段保留 `semantic_verified=false`。候选同等级继续保留先前稿，公开 ex02 所暴露的“如何可靠选择两个编译通过候选”尚未获得通用解决证据。本次没有把策略改成总选末稿。
