# V10：把时序推导前置，减少无效修复

**后续完整题集开发测试已补齐：21/21 判定，8 个 L3、9 个 L1、4 个 L0；历史同题功能从 7/21 到 8/21，生成耗时增加 26.25%。见 [完整测试与分析](v10_qwen_complete_20261027.md)。以下为当时尚无模型样本的迭代阶段记录。**

当前版本 `2026.10.27-v10-qwen-only`，**待固定千问实测**。已备份 V9，完成 294/294 项本地回归，未产生模型新样本、云实例或积分消费。V9 的 7/21 是历史开发结果，不能作为 V10 成绩。

## 依据与改动

[V9 实测](v9_qwen_hackathon_20261027.md)仍有 11/21 题停在 L1、3/21 题为 L0。13 套实际执行的自检中，8 套误拒正确参考；10 次代码修复只有两题最终代码变化，均未新增功能通过。此次优先处理影响功能分的共性原因。

| 改动 | 预期作用与边界 |
| --- | --- |
| 设计前的一次行为规划 | 明确时序任务先由同一千问说明状态含义、复位、事件接受条件、旧值到新值及输出发布时刻，再生成 RTL。规划仅供设计，独立验证看不到；格式合法仍可能语义错误。 |
| 明确采样沿契约 | 只从题面直接、无歧义的单比特输入采样沿取约束。DUT 和独立结构化验证计划分别核对；相反沿在后续工具和自检前反馈。复位触发沿、例子、否定、条件与多时钟不强行推断，宏、别名、层级和参数分支保守交给 HDL 工具。 |
| 同轮保留多个编译根错误族 | 最多四条根诊断、三个错误族，在一个不超过 3000 字符的反馈中给出策略。补齐 ANSI 端口重声明、枚举位宽范围诊断；过程赋值要求在原端口声明处修正类型，避免修复又引入重复声明。 |
| 澄清状态与观测含义 | 通用规则区分内部进度和对外发布值、事件组合优先级及沿前旧状态。盲复核明确 sample 是日志序号，不能直接当作输出值、周期或事务计数。 |

行为规划默认 `--planning-mode auto`，一次调用最多占剩余时间的 15%，上限 30 秒、1536 输出 token；剩余不足 60 秒时跳过。无效 JSON 或模型服务失败直接进入设计，不为规划增加恢复请求。`--planning-mode none` 可关闭该阶段。其余调用预算保持原值。

没有题号匹配、固定答案或专用 RTL 替换。脚本只处理结构与明确规格检查，硬件与参考算法仍由固定千问生成。规划可能增加开销；对这 21 道历史规格，路由会触发 13 题，不能预先宣称整体提速。

## 验收证据

- **294/294 本地回归通过，0 失败、0 跳过**，比 V9 新增 41 个测试方法。涵盖规划隔离、预算不足、无效回复和服务失败回退，独立计划不得覆盖明确采样沿，接口改名、边沿和复位变体，以及复合编译诊断。
- 实际 Icarus 正反控制中，符合下降沿规格的实现通过，相反沿实现触发功能断言失败。受控模型回复只验证流程，不能作为千问能力样本。
- 只读重放 V9 的 21 个旧候选：最终保守规则提取 4 个明确时钟契约，发现 1 个已知错误沿；历史 L3 候选误拒为 0。早期检查提取 7 个契约，加入复位上下文排除后收敛为 4 个，降低误判风险；未修改旧候选或旧成绩。
- 重放 10 份真实编译诊断：4 份可同时提供多个错误族的策略，2 份原 unknown 现在可识别。没有新模型执行这些修复，因此尚不能证明调用数或 L0 比例下降。
- 受限运行环境曾阻止本机测试连接和 Icarus 子进程；在正常本机权限下复验全部通过。该失败单独保留，不按 RTL 功能失败统计。

审查还修正了隐式 generate 分支可能造成的静态误拒、复位触发沿被当作时钟、规划状态名提示与解析器约束不一致，以及启动脚本未确认守护进程便报告成功的问题。

## 官方更新与部署

核对官方 RTL `fc8e26a5828b7222e9db439cee29128bcf4f8865`：评分公式、异步协议和基线原文件未变。Dockerfile 固定该版明确给出的平台基础镜像摘要；`serve/run_api.sh` 按官方方案适配本工程标准库 HTTP 服务，退出后等待两秒重启，并检查守护进程是否启动。无令牌健康检查、带令牌就绪检查通过后再暴露隧道；短时服务恢复不等于已经撤销的隧道恢复。
