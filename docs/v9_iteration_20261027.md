# V9：减少格式恢复和无效修复（2026-10-27）

**后续固定千问实测已完成：V9 功能 7/21、生成阶段 903.863 秒、费用 1 积分，实例已销毁，见 [完整测试与分析](v9_qwen_hackathon_20261027.md)。** 以下记录为本地迭代阶段，当时没有模型新样本、云实例或积分消费；V8 的 7/21 不被当作 V9 成绩。工作于 10 月 26 日开始，27 日完成，因此证据和备份目录保留起始日期。

改动前已保存 V8 备份（开发归档路径，未随库交付：`../../backups/rtl-v8-before-v9-20261026.zip`），包含 536 个源码、测试和说明文件，排除运行目录、工具安装和私有环境文件。当前版本为 `2026.10.27-v9-qwen-only`。

## 改了什么，为什么

依据 [V8 完整实测](v8_qwen_hackathon_20261026.md)：18 个验证计划有 14 个初稿结构失败，其中 5 个首先卡在临时变量前缀；12 套实际自检有 7 套在本地误拒正确参考。9 次代码修复累计 143.393 秒，未新增功能通过题。

| 改动 | 作用与边界 |
| --- | --- |
| 紧凑计划的临时变量由程序规范命名 | 按声明的角色一致替换标识符，保留表达式、位宽、signed、声明顺序；不猜状态或补算法。端口、状态、保留名和映射冲突仍拒绝，输出读取、未知符号、自引用、前向引用仍拒绝。 |
| 功能修复不再附带完整自建 TB | 保留规格、原 DUT、绑定失配、采样控制、真实输入历史和盲复核依据。完整日志与 TB 仍落盘，原 TB 不变并继续复验，避免再次把可疑参考算法送入修复上下文。 |
| 补齐多驱动诊断 | 真实的 `invalid combination of procedural drivers` 日志不再归入 unknown；反馈要求查全赋值、统一驱动并保留复位、边沿和并行旧值语义。 |
| 保守识别格式重复候选 | 普通空白/注释变化不再触发重复工具检查；数值、位宽、signed、运算符和标识符变化仍区分。预处理、属性、字符串、转义名及工具指令注释等复杂形式回退原字节比较。 |
| 调整通用设计与验证清单 | 列全无事件、各事件单独发生、同时发生和复位路径，核对事件接受条件、清除/消费和输出发布时刻。没有题号匹配、固定答案或题目专用修补。 |

修改的运行文件为 `agent/main.py`、`agent/repair.py`、`agent/verification_plan.py`、`agent/prompts.py` 和两份运行时规则。已有旧/新状态分离、原子提交、auto 刺激、盲复核及一次归因只修复一次均保留，不计作本轮新增功能。

## 验证结果

最终 **253/253 项本地回归通过，0 失败、0 跳过**，含 19 个新测试方法。测试覆盖实际 Icarus 仿真、正确/错误实现、错误 oracle、3/11/37 位变体、命名冲突、数字字面量、符号与运算符边界，以及受控修复流程。早期测试发现曾重复计入 3 个导入的旧用例，最终统计已去重。

只读回放 V8 的 18 份初始计划：直接结构合法 **4→5**，解析退步 0，原 4 套可接受 TB 的生成字节保持一致。其余命名错误后仍存在缺失端口、非法系统函数或语义边界错误，继续拒绝；没有宣称消除全部 5 次命名恢复。

新增可执行的 1 套旧计划分别对正确参考和原候选执行本地 Icarus 仿真，**两者都触发断言失败**。正确参考在 sample 12 的实际输出为 1、oracle 期望为 0。这证明命名修复只减少结构障碍，没有修好参考算法；该控制结果不写回 V8 原成绩，也不计为 V9 功能成功。

归档编译日志中的 2 个 unknown 诊断现在识别为多驱动；没有发现旧候选中额外的纯格式重复，因此不能从这批归档数据声称去重已节省实际时间。精简修复上下文的完整性及固定 TB 重用由流程控制验证，真实模型耗时仍未测量。

代码审查发现并修复了规范命名时可能误替换指数数字内部字符的问题；新增指数、小数、下划线位宽和基数字面量边界控制。建议中的“拓扑排序可解决历史依赖失败”未采用：归档案例实际是临时变量自引用，仍须拒绝，不能将其擅自改为持久状态。

## 一致性与限制

固定千问权重、量化、32768 上下文、单槽、thinking=false、采样和调用预算保持原配置；未使用其他模型生成测试样本。官方基线原文件、推理服务、接口解析、工具执行和独立判题器未修改；本地 Git 对象用于核对原样基线。

本轮尝试访问 Gitee 远端失败，按已核对的 RTL `51fbf8dc169bb320e6691c2ced34f331c2659ac0` 及其本地 API 契约完成局部实现；没有声称最新远端无变化。没有重新部署 Vivado 2026.1 或正式评测服务。

语义错误仍是主要风险。更容易执行的错误 oracle 可能增加误判，盲复核也仍可能推导错误。V9 的正确率、端到端速度和未见题泛化均未验证，不能换算为正式前 70 分。下一次按项目测试 skill 只测 V9，保持同一固定千问；云端费用需在有效授权内，已结束 V8 批次的余额不自动沿用。
