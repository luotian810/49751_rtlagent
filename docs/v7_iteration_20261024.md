## 改动及依据

V6 最近复测为 7/21，前一轮同版为 8/21。最近一轮验证计划及格式恢复消耗 720.097 秒，占模型调用时间 68.3%；18 个计划只有 7 个最终可执行。7 套生成测试台中，3 套误拒正确参考；一次错误归因还触发了无效设计修复。详见 V6 原始归因（开发归档路径，未随库交付：`../../output/rtl-v6-qwen-retest-20261024/FINDINGS.md`）。

1. **程序生成通用刺激。** 新的显式 `stimulus.mode=auto` 负责 7 组位宽边界、64 组固定种子随机输入和复位调度。超过 32 位的输入使用多个随机字拼接，避免高位只有符号扩展。模型仅补规格专有的定向序列；每条缺省输入是零、复位无效，不继承上一条。原显式模式仍严格拒绝缺键、时钟键与未知符号。程序不生成 DUT 或参考答案。
2. **格式恢复带原稿。** 以前只给错误让模型重新写整份计划；现在把原计划作为数据回传，要求修改有诊断依据的字段。恢复仍最多一次，功能失配不修改测试期望。
3. **盲推失配期望。** 结构化流程只给模型规格、采样控制、实际输入历史和目标输出名，不给 DUT、参考算法、实际输出或测试台期望。组合电路只需当前输入；时序电路须有最近有效复位以来的连续历史，最多 64 条。历史缺失或输入未知就停止归因，保留候选。模型独立给出期望后，程序比较双方数值决定是否允许一次修复；不信任模型直接宣判 DUT 有错。推导仍是模型假设，明确记录 `semantic_verified=false`。
4. **收紧通用设计方法。** 清单强调一项历史只有一个权威状态表示，完成事件后保留必要历史；数学简式须与规格量等价；区分旧状态、下一状态和发布的输出，不重复计入当前事件。这些规则不按题号、题名或答案分支。

## 验证结果

| 验证 | 结果与边界 |
| --- | --- |
| 完整工程回归 | 200 项通过，0 失败、0 跳过，20.263 秒；含 15 项新增机制测试 |
| Icarus 机制控制 | 覆盖 1/9/35 位输入、改名端口、8 种采样沿/复位组合，正确实现通过，错误实现被拒绝 |
| 本机 Vivado 2025.2 | 6 个控制符合预期：4 个正确实现通过，2 个错误实现产生功能失败；两条失败均可提取盲复核输入历史 |
| 历史归因上下文回放 | 3/3 可生成完整新请求；系统提示与用户请求合计 27,375 → 4,368 字符，减少 84.0% |
| 固定千问 V7 新样本 | 未运行；正确率、实际生成总耗时和 Vivado 2026.1 新版本兼容性待测 |

上述字符比较包含三次请求的系统提示和用户消息，不是 token 数、输出量或延迟测量。未重新推导历史题的答案，也未重算 V6 等级。auto 只降低确定性结构的生成负担，无法保证模型选择它或降低总调用数。

初次本地测试遇到沙箱临时目录权限拒绝，随后在获准的本地执行环境运行成功。完整回归首次有 1 个旧测试替身仍解析旧归因消息；更新替身为从实际输入独立计算期望后，200 项全部通过。失败记录保留；没有放宽运行时校验。

按官方 FAQ Q4，本机 Icarus 结果仅作机制证据；本机 Vivado 2025.2 也不能代替云端 2026.1 判定。通用随机刺激不能覆盖所有协议序列，模型仍须补定向测试；独立期望仍可能推导错误；无可重放复位历史时会放弃一次可能有效的修复。这些是下一轮固定千问测试要观察的风险。
