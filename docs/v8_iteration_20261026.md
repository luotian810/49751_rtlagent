## 实现

1. **生成测试台前先展开 DUT。** 智能体显式调用 `lint(..., elaborate=True)`；Vivado 在同一工作区完成 xvlog 和顶层 xelab，不运行 xsim，不需要模型生成测试台。Icarus 原有命令已包含展开，仍只执行一次；ModelSim 增加只加载顶层、不执行 run 的路径。普通 `lint()` 默认调用行为保持原样，独立判题不自动采用新门槛。
2. **按实际完成的阶段保存候选。** 内部证据分为接口、编译、展开、已执行断言、自检通过、综合通过；它们不是比赛 L0–L3。不同候选只有更强证据才替换旧稿，同级继续保留原稿。只启动进程、超时或工具故障不升级功能证据。即使测试台仍生成失败，已经从无法展开改到能展开的修复稿也能被保留。
3. **给编译修复可定位的反馈。** 新 `agent/repair.py` 从真实工具日志保留首批根诊断，过滤连带错误，附诊断行附近的实际源码。分类只涉及常量表达式限制、语法、过程赋值目标、缺失模块等语言/工具问题，没有题号、题名或答案分支。反馈最多 3000 字符；未知诊断保留日志，不猜原因或源码位置。
4. **识别无进展修复。** 归一化诊断去掉工作目录、行号及可安全替换的标识符，保留语法 token 和未知错误差异。相同阶段根错误复现时要求改写非法表达结构，而非只改名；仍使用固定千问、原最大轮数和剩余时间。完全重复候选仍立即停止。每轮保存 `compiler_diagnostic.json` 和 trace，便于实测修复是否有收益。
5. **区分工具故障。** 缺工具、许可证、超时继续单列。实际本地验收观察到沙箱中 xelab 的宿主 C 编译失败，新增 opt-in 预检对此记为工具 `error`，避免要求模型修改正确 RTL；没有放宽检查或把失败算通过。

主要源码：[主流程](../agent/main.py)、[工具检查](../agent/verification.py)、[编译诊断](../agent/repair.py)、[设计规则](../skill/rtl_rules.md)。原始 DUT 和模型回复仍完整保留；新的通用反馈不生成或替换 RTL 答案。
