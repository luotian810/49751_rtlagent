# 千问补测：45 个样本的完整失败分析

日期：2026-10-23（北京时间）。本报告只使用本批固定 Qwen3-14B-Q4_K_M 证据，未调用其他模型，也没有修改当前或冻结源码。每个题目/版本各生成 1 次，属于开发补测，不能当作正式五次 pass@1 或比赛分数。

**主要结论：V4.2 改善了自检执行能力，但没有带来本批可比较题集的功能提升。当前最优先的问题是验证计划的生成契约和 oracle 的语义可靠性；继续堆检查清单或增加修复次数解决不了。** 同一批 12 道泛化题，官方基线 3/12、V3 3/12、V4.2 2/12。V4.2 另有补充题 4/6、公开题 1/3，总计 7/21；由于题集不同，不能拿 7/21 与另外两组的 3/12 直接计算提升。

## 实验与证据范围

- 模型：Qwen3-14B-Q4_K_M，revision `c75e7b2d0234068f674a1bacf548ea32e27ccd29`，权重 SHA-256 `500a8806e85ee9c83f3ae08420295592451379b4f8cf2d0f41c15dffeb6b81f0`。
- 同一千问服务、32768 上下文、单槽、thinking=false；官方基线文件原样保留，单次 temperature=0；智能体 temperature=0.2。每题内部预算 240 秒、生成进程上限 250 秒，是开发实验设置。
- 固定独立评测使用 Vivado 2026.1、`xczu3eg-sbva484-1-e`、5 ns；21 份参考实现先通过 L3。45 个唯一任务全部完成，无独立评分环境错误。
- `results/summary.json`、`results/generated/`、`results/independent/` 为云端原始证据。`full-failure-analysis.json` 保存逐样本、逐阶段统计及原始错误索引。
- 为解决新疑点，仅追加了 13 个本地 Icarus 控制：7 份生成 TB 分别验证已通过固定评测的正确参考实现，另评 6 份未选中间稿；结果位于 `full-offline-diagnostics/`。没有重跑全部 45 个最终产物。这些控制不计作新增生成样本，也不改变云端结果。
- 首 8 个样本的早期诊断和 18 份文件交叉复验仍保留在 `early-analysis.*`、`early-offline-replay/`；本报告不再次执行它们。

V3 原始 TB 生成另有 **2/11** 次 token 截断；一次格式恢复碰到内部模型调用限时，按预算终止。这不是独立判题器/许可证故障。两组都没有通过无限重试或重投失败任务来掩盖失败。

## 自检可靠性：语法成功之后仍有严重问题

对 7 份真正执行的生成 oracle，使用冻结、已知正确的参考实现作为 DUT，保持生成 TB 完全不变，本地 Icarus 得到 **6 份错误拒绝正确参考、1 份通过**。这证明问题不只是 DSL 格式难生成；参考算法本身也经常错误。

| 工作流 | 正确参考跑生成 TB 的结果 | 已验证或源码可见原因 |
| --- | --- | --- |
| practice/p05_detect1011 | FAIL，sample=5，actual=1 expected=0 | next 的 ref_detected 读取旧 4 位历史，使检测延迟一拍 |
| practice/p06_serial_parity8 | FAIL，sample=2，parity=0 expected=1 | 把每一位累计 XOR 直接当输出；规格仅在第八位提交一组结果，且计数没有按组回绕 |
| gen_v2/v2_01_signed_sat8 | FAIL，a=127,b=1，actual=127 expected=-128 | stim_sum/ref_sum 只有 8 位，先截断再判断溢出，且 expected 直接输出截断和，没有饱和 |
| gen_v2/v2_02_counter_priority | PASS | 本次生成模型与固定参考在这些激励上一致；不构成完全正确性证明 |
| gen_v2/v2_05_enabled_101 | FAIL，正确参考最早在 sample=4 被误拒绝 | 历史更新有额外旋转，暂停也移位，match 用旧完整历史而未包含本拍输入 |
| gen_v2/v2_06_round_robin4 | FAIL，sample=10，actualgrant=1 expected=8 | 将沿前 temporary grant 拿到指针更新后的沿后比较；扫描和指针更新另有语义错 |
| public/ex02_detect_1101 | FAIL，sample=4，actual=0 expected=1 | 仅保留更新后 3 位，见到 110 三位就预期命中四位模式 1101 |

本批唯一自检 PASS（counter_priority）也通过固定评测，因此**观测到的自检假阳性为 0/1**；只有一次正例，不能宣称可靠。按最终样本二分类，智能体 33 个样本中 TP=1、FP=0、FN=9、TN=23；其中大多数 FN/TN 是验证未执行，并非 oracle 运行后的真实判断。应与“实际运行的 7 个 oracle 中 6 个会误报正确参考”分别报告。

V4.2 六次功能诊断中，5 次返回 dut_error，1 次 uncertain；五个 dut_error 都由上述会误拒绝正确参考的 oracle 触发。这里不能由“题面引用齐全、三个字符串满足相等/不等关系”推出推导真实。例如 signed_sat8 的日志只有 `y=7f expected=80`，诊断却自行补出 `saturated=0`，将本来正确的 y=127 说成 DUT 错；序列题把三个有效输入误说成已经有四个。当前 `parse_diagnosis` 只做字段完整性和字符串关系检查，不将观察值、采样历史与实际日志绑定。

## 三个必须解释清楚的结果

### 公开序列检测 ex02：已产生正确修复，最终选择仍失败

首稿 `results/generated/v42/public/ex02_detect_1101/solution.v:21` 检查旧 `state==3'b101 && in`，实际实现 1011，题面要求 1101；固定评测最终 **6/226 失配，L1**。

`round_02/solution.v:21`、`round_03/solution.v:21` 已改为 `3'b110 && in`。本次新增离线固定测试确认两份均 **0/226 失配**，并非仅凭肉眼推断。可是生成 oracle 在 `sample=4 reset=0 in=0`、只收到 110 三个有效位时，已要求 detected=1，所以两份正确修复仍被同一个坏测试台拒绝。候选规则不允许相同编译等级的不同代码替换首稿，最终保留了错误首稿。

这是本批**已证实的候选选择损失**。不能据此简单改成“总取最后一稿”：正确修复需要可置信验证证据；无条件换成新稿可能破坏原来正确的题。

### LFSR ex03：不是空解，而是相同端口声明错误未修复

最终 `solution.v` 为 **723 字节**，三轮 SHA 完全相同，不是空文件。ANSI 端口 `output [7:0] q` 后，模块内再次 `reg [7:0] q`，Vivado 三轮都报 `VRFC 10-9336 redeclaration of ANSI port 'q' is not allowed`，未进入计划或功能自检，固定评测 **L0**。`selected_round=3` 仅是相同候选合并新证据，不代表第三轮产生改进。复位/装载/反馈表达式静态上与参考相符，但没有通过编译，不能写成已验证的功能正确或错误。

真正的最终空解是 V4.2 `gen_v4/v4_02_signed_addsub6`：三轮都擅自把 `rhs_i[5:0]` 改成 `[6:0]`，被接口校验拒绝；三轮文件 SHA 相同，另含非法 `6'd-32` 字面量。接口检查发挥了作用，模型修复没有进展。

### Round-robin：DUT 和 oracle 都错，首次自检失败却不是 DUT 错

最终 DUT 将下一优先级设为 `(p+1)%4`，规格要求跳到**实际授予 client 之后**，固定评测有 **361/1120** 次失配。生成 plan 也犯了相同指针错误，并且扫描 `ref_p+k` 没有取模回绕。

首次自检失败为 `sample=10 req=f accept=1 grant=1 expected=8`：此前接受 client 0/1/2 后，沿前 p=3、grant=8；本拍接受 client3 后 p=0，组合 grant 应立即变成 1。生成 TB 仍把沿前 `stim_grant=8` 用作沿后期望，故这次是 oracle 误报；正确参考也在同一条断言失败。诊断最终降为 uncertain、没有继续修 DUT，方向上避免了据错误断言盲改，但尚未解决实际的指针算法错误。

Vivado 对局部声明初始化给出了 lifetime warning，这是静态可移植性风险；没有隔离实测证明它导致了本次全部失配，不能与已证实的指针/采样错误混写。

## 其他跨题型错误与候选选择

1. **旧状态、本拍输入与输出提交时刻。** 三样本求和漏写第三样本，求和读取尚未写入的 `samples[2]`，又额外延迟输出；使能序列检测使用旧 shift_reg 比较，导致命中晚一拍；串行校验 IDLE 不接收首位、终值读取旧校验寄存器。固定失配已经实测，具体语句如何造成错拍来自源码静态分析。
2. **握手和同时操作。** elastic buffer 声称满且 out_ready 时 in_ready=1，但内部只在空时写入，导致同拍取出/补入丢新数据；两种 FIFO 出现多进程驱动 count/full/empty、错误指针和不完整组合信号。这类问题须从实际接受事件推导下一状态，不能由“写路径+读路径”独立拼接。
3. **表达式和工具阶段。** 循环移位既有动态普通切片导致编译错，也有拼接后截断导致功能错；V3 generate 在 i=0 产生非法范围，xvlog 通过但 xelab 失败。lint 成功不代表完整 elaboration 成功。V3 的 9 份已生成 TB 全部未执行 xsim；其中 7 题语法恢复后仍失败，2 题编译/elaboration 错误未被工具错误分类捕获，被误送功能诊断。
4. **重复修复。** 10 个工作流出现多轮 DUT；其中 5 个三轮候选 SHA 完全一致：V4.2 signed_addsub6、signed_sat8、enabled_101、LFSR，以及 V3 FIFO3。其余部分修复稿第二、三轮也重复。增加轮数没有增加证据。
5. **选择安全性有保护也有损失。** p05 的最终原稿已通过固定测试；未选修复稿也通过 2830 项固定检查。parity 的未选修复稿仍在固定 check16 失败；FIFO2 审查稿仍编译失败，FIFO3 审查稿仍 1560/1560 失配；早期 rotate12 审查稿仍 115112/131072 失配。不能把所有未选稿都算成“本可提分”。目前确认丢失正确新稿的是公开 ex02。

## 下一版建议：先做这五项

1. **把 schema 约束变成程序生成的合同，减少模型抄接口和跨字段引用。** 固定接口、时钟/复位声明由可信题面契约统一提供；临时量声明与表达式放在同一记录，状态声明与 next 绑定；values 自动按既定非时钟输入键生成骨架；数组写入单独类型。保留严格边界，不能为了通过校验自动猜位宽、放开 DUT 输出读取或任意代码片段。
2. **验证计划先达到可运行且语义可信，再允许驱动修复。** 对位宽/有符号、当前输入、旧/新状态和 pre/post-edge 输出显式建模。组合输出随状态更新时，沿后 expected 必须重新计算，不能默认复用沿前 temporary。开发阶段用正确参考和跨类变异体验证 oracle；正式生成仍不能接触参考答案或外部固定测试台。
3. **把失败证据绑定到实际日志和有限历史。** 机械校验 sample、信号值和进制是否真的出现在 FAIL/VCD 中，保存最近若干采样的 reset/enable/输入/参考状态；诊断不得补写未观测输出。表述自洽不能当证明。遇到不一致应暂停基于该 oracle 的改写，记录为验证不可信，而不是反复让 DUT 迎合它。
4. **分清分析、展开、运行，给结构错误做有界修复。** lint 包含 elaboration 或明确标注只做语法；使用结构化阶段/源文件归属路由 TB 问题，补充常量切片、复制次数、generate 边界、ANSI 声明与表达式语法诊断。JSON 不完整与完整 JSON 的结构修复分开，后者避免不必要的整份重写。
5. **检测无进展并保留可比较候选，不无条件取首稿或末稿。** 相同候选 SHA+相同错误再次出现就停止重复消耗，返回具体字段与原始错误。保留未选稿及其证据；只有可信验证才用于升降候选。公开 ex02 证明当前强制使用坏 oracle 会丢失正确稿，但“总取最后稿”不能安全解决此问题。

下一轮仍应锁定相同千问、相同官方基线和冻结测试设置，先验证以上机制是否分别提高“计划合法率、真正执行率、正确参考接受率、变异体拒绝率”，再看固定功能通过率。此次结果不支持将 V4.2 标记为已有效提分版。
