# 设计与阅读说明

本工程接收 RTL 题面，使用固定本地 Qwen3-14B-Q4_K_M 生成设计与独立验证计划。模型承担硬件和参考算法设计；程序负责格式、调度、工具运行和证据保存。生成端只读取 prompt.txt 及可选显式接口，不读取参考实现或外部测试台。

## 主路径

```text
题面 → 明确时序任务的一次行为规划 → 千问生成 RTL → 接口/明确采样沿检查 → DUT 编译
                                  ↓
                  独立规格计划 → 固定测试台 → 仿真
                                  ↓
             编译/展开错误按来源修复；实际失配做观察绑定诊断
                                  ↓
                  一次有依据的修复 → 更强证据才替换候选
```

V5 去掉每题固定的额外设计审查，合并测试台请求的解析、记录和启用路径。验证计划编译器分为解析、接口/控制校验、算法规范化、刺激编译、模板生成，旧保存计划与紧凑新计划共用一个执行骨架。

V10 的行为规划只给设计端提供状态含义、事件接受条件及输出发布规则，最多一次、30 秒和 1536 输出 token；剩余不足 60 秒时跳过，格式或服务失败直接设计。规划不构成语义证明，也不进入独立验证。只有题面明确且无歧义的单时钟沿才进入约束；DUT 与结构化验证计划分别核对，复杂 HDL 结构交给展开和仿真。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `agent/main.py` | 读题、预算、调用与修复顺序、候选保存 |
| `agent/interface.py` | 模块提取、可靠签名和位宽/符号解析 |
| `agent/behavior_plan.py` / `agent/timing_contract.py` | 有界设计规划、保守的明确采样沿契约 |
| `agent/prompts.py` / `skill/` | 角色契约及通用 RTL/验证知识 |

| `agent/diagnosis.py` | 将归因字段绑定到实际 FAIL 采样点 |

| `serve/` | 常驻启动、异步协议、任务回收 |

## 计划的时间语义

可靠题面签名由程序固定，模型无需重新生成端口清单；无法解析时明确要求端口描述，不能猜位宽。临时量的声明与 expr 位于同一条记录；状态的声明与 next 或数组 writes 位于同一条记录。

每个 step 驱动输入，复制旧参考状态，按顺序计算临时量，再计算全部下一状态并同时提交。expected 读取提交后状态；临时量仍是本拍沿前值。时钟沿与复位极性来自题面；程序等待 NBA 稳定后比较，异步复位另作沿前检查。真实 SAMPLE 日志记录输入、输出和沿前/后阶段。

格式合法不证明参考算法正确。开发期使用独立正确实现和跨类型变异体检验骨架；正式生成不得获得这些答案。

## 失败与候选

工具返回实际阶段及错误源。编译/展开未运行到断言，不能进入功能诊断；看门狗、缺 PASS、许可和进程异常分别记录。明确属于 TB 的结构问题可在共享的一次恢复机会内处理；功能失配保持 TB 不变。

归因只接受真实 FAIL 的采样编号、全部输入、同名输出和测试台期望；缺失历史或编造信号使其保留不确定。日志绑定只核实观测，不能证明模型从题面推导的 expected 正确。一次功能归因最多推动一次 DUT 修复，修复仍失败则停止沿用。

所有轮次保留候选与回复。完全重复候选立即结束，减少重复 EDA 和后续调用。同等级仍保留先前稿，只有更强检查证据才替换；没有可靠独立证据时不强行解决候选优劣。原子写入 solution.v，异常和超时时保留已保存候选。

## 实测与未验证部分

V4.2 的 45 样本千问实测显示验证计划难生成、错误 oracle 多、修复收益低；V5 据此改进机制。结果见 [失败分析](qwen_failure_analysis_20261023.md) 与 [V5 记录](v5_refactor_20261023.md)。新版本能力与墙钟增益仍需千问同配置实测，当前工程回归不能替代。

官方 baseline 原文件及输入隔离保持不变。当前模型权重、上下文、推理配置和历史测量范围见 manifest.json；完整离线重建、平台连续投题与正式成绩以实际后续证据为准。
