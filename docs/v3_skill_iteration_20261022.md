## 从失败到修改

| 实测问题 | V3 修改 |
| --- | --- |
| 旧规则只进入设计调用，测试台先例化后声明、过程赋值到 wire、task 参数遮蔽等问题未得到约束 | 新增 `verification_rules.md`，实际加载到独立 TB 生成、格式恢复和编译修复；要求先声明、驱动类型正确、单驱动和不同名形参 |
| 测试台参考状态读取 DUT 输出、漏复位，正常完成与看门狗竞争 | 独立参考状态按规格从复位推进，所有刺激走同一参考算法；完成检查立即结束 |
| 未生成完整 tb、回复截断或缺 PASS/FAIL 后直接退出 | 剩余至少 20 秒时允许一次紧凑完整重写，只给规格与格式原因；不续写不完整稿 |
| Vivado 非寄存器赋值、隐式重复声明及连带诊断未正确进入 TB 编译修复 | 按源文件归属识别；混合 DUT 错误、端口/例化契约问题和功能 FAIL 不进入自动 TB 修复 |
| 已有泛化的 next-state 提醒，仍出现常量截断与晚一拍 | 重组设计规则，要求核对常量可表示范围、固定切片宽度、移位边界，并逐拍检查旧状态/当前输入/新状态/本拍输出及分组边界 |

格式重写与编译修复**共享一次恢复机会**，继续受单题总墙钟约束。新格式恢复调用最多使用剩余时间的 25%、上限 60 秒、3072 输出 token；未增加总解题预算。功能失配仍先诊断，不能通过改测试期望迎合 DUT；失败或不确定时保留已保存候选。

原题通过 JSON 的 `specification` 字段提供给验证角色，明确原题“只交 DUT”的交付要求不覆盖当前 TB 任务，接口和行为保持题面约束。这解决的是潜在角色冲突；尚无新模型采样证明它减少了实际漏生成。独立审查另发现固定上升沿检查会与下降沿规格冲突，现已改为遵循题面的有效采样沿与延迟。

技能入口为 [SKILL.md](../skill/SKILL.md)，调用阶段分别读取 [设计规则](../skill/rtl_rules.md) 和 [验证规则](../skill/verification_rules.md)。规则未包含六道练习的答案、端口常量或特定检测模式；隐藏 TB、参考实现仍不进入生成上下文。
