# V11：对照标准基线，减少低收益调用并补齐验证入口

当前版本 `2026.10.28-v11-qwen-only`，**待固定千问实测**。V10 已备份，V11 的 310/310 项本地回归通过，0 失败、0 跳过。本轮没有模型新样本、云实例或积分消费；没有把历史成绩归给 V11。

## 标准基线比较

采用 2026-10-23 完整批次中的原样官方 baseline 组，逐题对照 V10 配置一致、互不重复的 7+14 两批。21 道题及独立判题依据一致；原始归档、冻结来源和官方基线字节已核验。没有跨批次挑选最好结果。

| 历史开发结果 | 原样官方基线 | V10 |
| --- | ---: | ---: |
| 功能通过 | 7/21 | 8/21 |
| L3 / L1 / L0 | 7 / 12 / 2 | 8 / 9 / 4 |
| 模型调用 | 21 | 77 |
| 生成阶段总耗时 | 130.729 秒 | 1141.123 秒 |

V10 相对基线 **3 题新增通过、2 题丢失通过**；生成耗时为 **8.73 倍**。净增一题不足以抵消明显的耗时问题，也不能掩盖回退。详细逐题结果、原始摘要及可比性核验见 [基线比较](../../output/rtl-v11-iteration-20261028/baseline-comparison/COMPARISON.md)。

主模型、权重、量化、32768 上下文、单槽、thinking=false 与 llama.cpp `f114f91` 一致。基线保留官方 temperature=0、top_p=1、16384 token、一次生成；方案为 temperature=0.2、设计上限 8192 token、带内部验证和修复。这是标准基线与完整方案的比较，不是只增减 skill 的纯消融。两者开发外层上限均为 250 秒；不是官方 900 秒、每题五次评测，也不是同批同步 A/B。本文不计算官方增益、代价分或总分。

## 问题与本轮改动

1. **额外规划成本高、采用率低。** V10 共 13 次行为规划，耗时 314.083 秒，只有 2 次被设计阶段采用，其余为结构错误或超时。V11 默认 `--planning-mode none`，在同一次设计请求中核对状态和事件；保留显式 `--planning-mode auto` 供旧机制对照。它确定省去默认独立规划阶段，但后续生成长度和修复次数可能变化，不能直接声称总时长减少 314 秒。

2. **基础算术与时序建模仍有回退。** 基线通过而 V10 失败的饱和加减出现无符号负边界表达；弹性缓冲遗漏“只消费”的清除路径。其他共同失败还涉及历史保持、同拍更新和输出发布。设计规则改为统一符号与扩位、列全事件组合、从同一旧状态推导、明确发布时刻；验证规则强调组合临时链不产生跨拍历史，并要求激励实际触发完成/命中事件。规则不含题号、模块名或答案，不替模型生成特定 RTL。

3. **明确端口还要模型重复填写。** 之前三个公开题的完整文字端口列表未进入固定契约。现在保守识别“明确模块名 + 完整连续端口列表”；省略位宽必须有局部的单比特默认声明。未知宽度、重复、复杂、冲突或不完整列表仍不推断。接口与验证计划共用这一契约，可靠类型同时检查方向、位宽与符号；不把未知用户类型当作无符号标量。

4. **已知输入下的 X/Z 输出被挡在盲复核之外。** 现在允许从真实、完整、连续且含有效复位的输入历史独立推导；实际输出和测试台期望仍不进入复核请求。只有独立已知期望与测试台期望一致、目标绑定和位宽合法时，才允许对未知输出归因为 DUT 错误并给一次修复。输入未知、缺历史、期望未知或双方期望不一致仍停止。模型独立推导不是语义证明。

这些改动保留现有预检、采样沿检查、候选保留、有限恢复和独立判题机制。官方基线、权重、服务配置、调用预算、独立判题器和测试台编译骨架均保持原样。

## 本地证据与边界

- **310 项回归通过**，包含比 V10 新增的 16 个测试方法。覆盖改名、1/7/35 位、符号、同步/异步复位与两种极性、缺失/未知历史、错误目标、上下文隔离和默认调用顺序。受控回复验证流程，不代表千问能力。
- 真实 Icarus 正反控制：正确异步复位实现通过；去掉异步复位敏感沿的错误实现产生 X，能进入绑定输入历史的盲复核。旧测试中的整数类型等价比较原先忽略了 signed，现修正为真实等价向量，并检查相反符号被拒绝；没有放宽类型检查来通过测试。
- 归档重放中，固定接口 **18/21 → 21/21**；17 份实际首次验证回复（包括非第一轮才触发验证的样本）结构合法数 **6/17 → 8/17**。两份新增合法计划对应历史格式恢复共 21.971 秒，这只是潜在可省的历史开销，不是 V11 实测提速。
- 新增合法不等于参考算法正确：序列检测的首稿仍把组合临时链当作多拍历史；另一份读取 DUT 输出的计划仍被拒绝。提示词澄清能否修正这些错误，尚无新千问证据。
- V10 和基线的 42 份旧候选均进行了接口检查，其中 **15 份 L3 候选误拒为 0**。一份真实复位 X 失败日志新增可用盲复核入口；旧候选、旧判级均未改写。
- 设计系统提示与规则字符数从 1102 降至 1005；字符数减少不等于 token 或时延减少。首次回归发现的旧符号等价断言问题保留在 `initial-regression` 日志；审查同时排除了正文以 input 开头被误判为新增端口的情况。

本轮没有新增外部参考机制；规则依据沿用已核对的官方 RTL `fc8e26a5828b7222e9db439cee29128bcf4f8865`，没有将其表述为本日远端最新版本。实测中 **11 套自检仍有 6 套误拒正确参考、1 套误放错误候选**，这是 V10 的关键剩余问题；本轮只能证明结构和复核入口改善，不能宣称语义错误已解决。

下一轮只测最新版 V11 的固定千问新样本，继续比较逐题等级、生成总时长、初稿与修复收益、参考实现接受率和误放率。该 21 题已参与开发，不能作为未见题泛化证明。历史云授权已关闭；此轮不启动付费实例。
