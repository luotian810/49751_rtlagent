## 实际发现并处理的问题

1. **隧道安装器经过实例代理返回 403。** 初次官方安装脚本退出码 22，完整失败日志保留。对同一官方安装器去掉大小写 HTTP/HTTPS/ALL_PROXY 后直连成功，安装 rc-tunnel 0.3.0，再对 7860 expose 成功。只恢复环境层，没有重新加载模型或重新生成候选。
2. **首次健康显存使用了加载前的采样。** 初始 health 为 0.267268096 GB，该快照不能代表加载后的模型占用。在首次投题前实际重新读取显存，后台重启投题 HTTP 进程，将 health 更正为 14.524166144 GB；模型进程没有重启。初始记录没有覆盖，当前及历史响应均在证据包内。
3. **Windows 本地检查脚本需要显式 UTF-8。** 初次读取返回 JSON 时触发 GBK 解码错误，随后显式使用 UTF-8 完成本机独立仿真。此问题没有重发投题或改变候选。
4. **V7 的内部测试计划仍有问题。** 本题共 3 次千问调用：设计 3.810 秒、独立测试计划 6.643 秒、计划格式修复 5.302 秒。两次计划检查均因临时变量未符合 `stim_` 命名规则而拒绝，`selfcheck_passed=false`，未执行 agent 自建功能仿真。本次功能正确来自独立判定，不能写作“内部自检通过”。原 trace 部分中文诊断存在编码损坏，结构字段和 `stim_` 原因可辨认；保留原文，不改写日志。

上述发现没有触发智能体、模型权重或运行时 skill 的优化。本次只测试链路，并更新部署说明。
