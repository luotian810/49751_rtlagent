# 设计检查清单

按规格完成核对后输出代码，不输出检查过程。

1. 固定接口契约中的模块名、端口、方向、位宽和符号不可改；未解析出的信息以原题为准。按题面确定采样沿、复位极性/同步性、控制优先级及输出延迟，不按信号名或常见题型猜测。
2. ANSI 端口只声明一次；过程赋值目标用 reg/logic。信号保持单一驱动，组合过程覆盖全部分支，时序过程使用非阻塞赋值。仅输出可综合硬件，不含测试控制、延时或时钟发生器。
3. 算术与移位先扩展操作数、明确 signed，再运算、判边界并截取结果；宽目标不能恢复已截断的高位。常量须可由声明位宽表示，尤其是除数和范围上界。混合符号、移位方向和表达式类型逐项核对。
4. 普通范围切片的边界须为常量；动态选择用位索引或固定宽度的索引切片。检查每个输出位的来源及丢弃/填充规则，不以反向操作恢复已丢失位。赋值与条件分支的类型保持兼容，枚举状态使用其声明类型。
5. 将内部进度/部分结果与对外发布结果分开定义；只有规格规定的发布事件才更新保持型输出，脉冲型输出在其余拍按规格撤销。每项历史只保留一个权威状态表示，定义含义、合法范围与初值。对控制事件列全“无事件、单独发生、同时发生、复位”的转移及优先级，不能遗漏清除或消费路径。接受事件用沿前状态判断；所有右值由同一旧状态快照推导，再同时提交新状态，当前输入只计一次。核对连续事件、暂停、重叠与复位后首拍。行为规划仅用于组织这些推导，仍须按原题复核。
6. 修复先区分接口、语法编译、层级展开、功能与工具故障。编译修复按实际诊断位置和相邻源码定位根错误；同类错误重复时改写非法表达结构，不能仅改名称或注释，始终保留规格不变量。展开须核对辅助模块、参数和实例端口；语法通过不代表展开成功。自建测试台 FAIL 只说明双方不一致，归因须有规格和真实激励依据；编译或自检成功均不代表正式功能通过。
